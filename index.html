Data Parallelism
DP
Batch / Sample

Replicates the full model on every GPU. Each GPU processes a different mini-batch and gradients are all-reduced across replicas after each step.

SplitsData (batch) across GPUs
BottleneckFull model must fit in one GPU's VRAM
Comm.All-reduce of gradients after each backward pass
Best forModels that fit in one GPU; scaling throughput linearly
Layer-level behaviour — no sequence or weight splitting
AttentionFull replica; full seq; no seq split
MLP / FFNFull replica; full seq; no seq split
LayerNormFull replica; full seq; no seq split
EmbeddingFull replica on each GPU
Gradient sync (post-backward)All-reduce across all DP ranks — only cross-GPU interaction; once per step
SCOPE
Intra-node → Multi-node (8–1000s GPUs). Scales freely via NCCL/RDMA; BW bound on gradient all-reduce.
ZeRO Stage 1
ZeRO-1
Batch / Sample Optimizer State

Like DP but partitions optimizer states (Adam moments, fp32 master weights) across DP ranks. Each rank keeps only its shard of optimizer state; params and grads remain replicated.

SplitsOptimizer states across DP ranks
Memory ↓~4× reduction in optimizer memory vs DP
Comm.All-reduce gradients (same as DP); scatter optim updates
OverheadMinimal over vanilla DP — drop-in replacement
Layer-level behaviour — identical to DP in the forward/backward
AttentionFull replica; full seq
MLP / FFNFull replica; full seq
LayerNormFull replica; full seq
ParamsReplicated on all GPUs
GradientsAll-reduced (replicated)
Optim StateSharded — each rank updates & stores only its 1/N shard
SCOPE
Same as DP — intra to multi-node. No extra scope constraints.
ZeRO Stage 2
ZeRO-2
Batch / Sample Optimizer State Gradients

Extends ZeRO-1 by also sharding gradients. Each DP rank retains only the gradient shard needed for its optimizer update; the rest is freed after reduce-scatter.

SplitsOptimizer states + gradients across DP ranks
Memory ↓~8× vs full DP (optim state + gradient sharding)
Comm.Reduce-scatter grads (instead of all-reduce)
BottleneckParameters still replicated on every GPU
Layer-level behaviour
AttentionFull replica; full seq
MLP / FFNFull replica; full seq
LayerNormFull replica; full seq
ParamsStill replicated on all GPUs
GradientsReduce-scatter; rank keeps only its own shard after backward
Optim StateSharded — each rank owns & updates 1/N shard
SCOPE
Same as DP — multi-node friendly. Slightly more comm. than ZeRO-1 but comparable scale.
ZeRO Stage 3
ZeRO-3 / FSDP
Batch / Sample Optimizer State Weights + Gradients

Shards optimizer states, gradients, AND model parameters across all DP ranks. Parameters are all-gathered on-the-fly just before each layer's forward/backward, then immediately discarded.

SplitsParams + grads + optim — everything sharded across DP ranks
Memory ↓Linear: model memory ÷ N GPUs + small working set
Comm.All-gather before every layer fwd; reduce-scatter after bwd
Best forModels far larger than a single GPU's VRAM
Layer-level behaviour — all-gather/reduce-scatter wraps every layer
AttentionAll-gather weights before fwd; reduce-scatter grads after bwd
MLP / FFNAll-gather weights before fwd; reduce-scatter grads after bwd
LayerNormAll-gather weights before fwd; reduce-scatter grads after bwd
EmbeddingAll-gather weights before use
GradientsReduce-scatter immediately after each layer backward
Optim StateEach rank updates only its own param shard
SCOPE
Multi-node (64–1000s GPUs). High comm. overhead; best with InfiniBand. Often paired with PP to reduce all-gather frequency.
Tensor Parallelism
TP
Tensor Width (Hidden Dim) Model Weights

Splits individual weight matrices column/row-wise across GPUs within a node. Each GPU holds a shard of every layer's weights (not full layers), computes partial results, then all-reduces to produce the full output.

SplitsWeight matrices along hidden dim within each layer
Comm.All-reduce after every fwd and bwd op — very high frequency
RequiresFast NVLink / NVSwitch intra-node bandwidth
Best forVery wide models; always confined to one node
Layer-level behaviour — hidden dim split; no sequence split here
QKV ProjColumn-split across TP ranks; all-reduce output
Out ProjRow-split; all-reduce merges partial sums → full hidden
MLP up/gateColumn-split; each GPU computes partial hidden
MLP downRow-split; all-reduce → full hidden dim output
LayerNorm / DropoutNOT split by TP — full hidden on each GPU. SP fills this gap (see SP card).
SCOPE
Strictly intra-node (2–8 GPUs). High-freq all-reduce is prohibitively slow over InfiniBand; NVLink mandatory.
Sequence Parallelism
SP
Sequence Length (Activations)

Companion to TP. Splits the sequence dimension in the regions where TP does NOT split activations — LayerNorm, Dropout, and the residual stream — eliminating redundant activation copies across the TP group.

SplitsSequence dim of activations in non-TP regions (LN, Dropout)
Memory ↓Activation memory ÷ TP degree for LN/Dropout/residual
Comm.All-gather entering TP region; reduce-scatter leaving it
NoteAlways paired with TP; SP degree always equals TP degree
Layer-level behaviour — SP only splits where TP does not
Attention + MLP (TP region)Hidden dim split by TP here. SP does NOT add a seq split — instead all-gather from SP state on entry into this region, reduce-scatter on exit.
LayerNormSeq split: each GPU owns seq/TP tokens
DropoutSeq split: each GPU owns seq/TP tokens
Residual streamSeq split; reduce-scatter on exit from TP block
SCOPE
Intra-node only (same GPUs as TP). SP degree = TP degree; inherits TP's NVLink requirement.
Context Parallelism
CP
Sequence Length (Long Context)

Partitions the full input sequence across GPUs for very long contexts (128k+ tokens). Each GPU owns a token chunk and processes it through every layer — MLP, LN, residual are all purely local. Only attention requires cross-GPU communication to exchange K/V across chunks via a ring all-to-all.

SplitsToken sequence — each GPU sees seq_len / CP tokens throughout the whole model
Memory ↓KV cache + ALL activations (MLP, LN, residual…) scale with seq_len / CP
Comm.Ring all-to-all for K/V at attention only — all other layers: zero extra comm
Causal LM ⚠Contiguous chunks cause load imbalance (token 0 attends to 1 past token; last token attends to S). Use interleaved / striped chunking (e.g. Llama 3 style) to distribute causal work evenly.
Layer-level behaviour — seq chunk flows through EVERY layer; cross-GPU comm ONLY at attention K/V
Attention⚡ Ring all-to-all: each GPU iteratively sends its K/V shard around the ring (CP-1 steps) to compute full-context attention scores. This is the ONLY cross-GPU op in CP.
MLP / FFN✓ Purely local — FFN operates on the local token chunk only. No cross-GPU comm needed (FFN is token-independent).
LayerNorm✓ Purely local — statistics computed on local chunk. (Note: if global LN stats are needed, extra comm required — rare in practice.)
Dropout / Residual✓ Purely local — element-wise ops on local token chunk.
Embedding✓ Seq split — each GPU looks up embeddings for its own token indices locally.
Causal mask (decoder)Each GPU applies a local causal mask to its chunk + receives past K/V from earlier-position GPUs. With contiguous chunks: GPU 0 is almost idle (few past tokens), GPU N-1 is overloaded. Fix: interleaved/striped assignment of token positions across GPUs.
SCOPE
Intra- or cross-node (2–64 GPUs). Ring K/V tolerates more latency than TP all-reduce; can span nodes with sufficient BW.
Pipeline Parallelism
PP
Layers / Model Depth

Assigns consecutive groups of transformer layers to different GPU stages. Micro-batches flow through the pipeline; 1F1B scheduling minimises the idle "bubble" at stage boundaries.

SplitsGroups of consecutive layers across GPUs (stages)
Memory ↓Each GPU holds only its stage's weights and activations
Comm.P2P: activations forward; gradients backward between adjacent stages
BottleneckPipeline bubble — GPU idle at batch start/end; grows with PP degree
Layer-level behaviour — each GPU owns a contiguous slice of layers
AttentionLocal on stage's GPU; full seq processed, no seq split
MLP / FFNLocal on stage's GPU; full seq processed, no seq split
LayerNormLocal on stage's GPU; no seq split
Stage boundary (between adjacent GPUs)P2P send/recv of full activation tensor fwd + gradient tensor bwd. Very small BW vs TP — works over InfiniBand or even Ethernet.
SCOPE
Cross-node (2–N nodes, 1 stage/node typical). Only activation tensor crosses node boundaries — very low BW; ideal for slow inter-node links.
Expert Parallelism
EP / MoE
Experts (MoE FFN)

Distributes MoE expert FFNs across GPUs. A learned router selects top-K experts per token; tokens are dispatched to expert GPUs via all-to-all, processed locally, then gathered back. Attention and non-MoE layers are unaffected.

SplitsExpert weight matrices across GPUs (≥1 expert per GPU)
Compute ↑Total params scale without proportional FLOPs increase
Comm.All-to-all token dispatch + gather per MoE layer
RiskLoad imbalance if router collapses to few popular experts
Layer-level behaviour — only MoE FFN layers are split; attention is untouched
AttentionNOT affected — local on each GPU, same as dense model
LayerNormLocal on each GPU; unchanged
RouterLocal softmax gate selecting top-K expert indices per token
Expert FFN (MoE layers only)All-to-all dispatch: tokens fly to assigned expert GPU → processed locally → all-to-all gather back. Dense FFN layers (if any) remain fully local.
SCOPE
Intra- to multi-node (8–1000s GPUs). All-to-all is BW-intensive; EP group often ≤1 node to avoid slow cross-node all-to-all.

Common Combinations (3D / 4D / 5D Parallelism)
Combination Why combine? Used by Example Scope / Config
DP + PP + TP Classic 3D parallelism. TP splits width intra-node (NVLink). PP crosses nodes cheaply (P2P activations). DP multiplies throughput across node groups. Megatron-LM, GPT-4 training TP=8 (intra-node, NVLink) × PP=4 (cross-node P2P) × DP=N → 32N GPUs. E.g. 128 GPUs = 4 nodes × 8 GPUs, PP=4 stages.
TP + SP SP fills the coverage gap TP leaves in LayerNorm/Dropout regions, eliminating redundant activation copies across the TP group at no extra GPU cost. Megatron-LM (always paired) Same scope as TP: 2–8 GPUs, strictly intra-node. SP adds zero extra GPUs — it's a scheduling change within the same TP group.
ZeRO-3 + DP Shards all state (params, grads, optim) so the full model never lives on one GPU, while DP scales data throughput. Enables trillion-param training without model parallelism. DeepSpeed, PyTorch FSDP 64–512 GPUs across 8–64 nodes (e.g. 512 A100s for a 70B model). InfiniBand required for all-gather; each GPU holds ~70B/512 = 137M params at rest.
CP + TP + SP + PP + DP 5D parallelism for ultra-long context at massive scale. CP handles KV memory growth (ring attn comm only). TP/SP handle width intra-node. PP crosses nodes cheaply. DP multiplies. Llama 3, Mistral Large TP=8 (intra-node) × SP (same group) × CP=4 (1–2 nodes, ring K/V) × PP=8 (cross-node P2P) × DP=N → 256N GPUs. Enables 128k+ tokens on thousands of GPUs.
EP + DP + TP EP distributes expert FFNs within a node (avoids cross-node all-to-all). TP splits attention and non-expert dense layers intra-node. DP replicates node groups across the cluster. Mixtral, DeepSeek-V2/V3, Switch Transformer EP=8 (1 node, NVLink all-to-all) × TP=4 (same node) × DP=N → each node hosts all 8 experts; DP scales across N node groups. Cross-node all-to-all avoided entirely.
